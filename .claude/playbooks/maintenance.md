# 制度檔維護協議（MAINT）

> 這套制度要能被安全地更新，否則第一次環境變化就會變成錯誤百科。本檔規定：誰能改什麼、教訓怎麼寫、多肥要瘦身。

## MAINT-1 修改權限分級

| 檔案 | 未來 session 可否自行改 |
|---|---|
| `lessons.md` | 自由 append（照 MAINT-2 格式）；**不可改寫或刪別人的舊條目** |
| `WORKLOG.md` | 自由編輯（本來就是工作檔） |
| `playbooks/*.md` 的規則內容 | 可改，但必走 MAINT-3 流程 |
| `CLAUDE.md` | **先問使用者**（它是每個 session 的載入面，改壞影響全域）。例外：純事實過時（指令改名、路徑搬家）可直接修＋記 lessons |
| `agents/*.md` | frontmatter 的 `model`/`effort` 可調（在 commit 訊息寫理由）；角色職責大改**先問使用者** |
| `diagnosis.md` | 「環境事實速查」表可更新（必附你怎麼驗證的）；三大失效模式的結構性改動**先問使用者** |
| `letter-to-future-sessions.md` | append-only 歷史文件：只能在末尾加註記，不能改寫原文 |

## MAINT-2 教訓怎麼寫（lessons.md）

**時機：踩坑的當下就寫（同一個 turn）**。留到收尾必忘。

固定四行格式：
```
## YYYY-MM-DD 一句話標題
- 情境：什麼任務、什麼操作踩的
- 代價：浪費了什麼（重做？錯誤結果？被使用者糾正？）
- 規則：一句可機械執行的祈使句（將來遇到 X 就做 Y）
- 去處：已併入哪個 playbook 條款，或「暫存於此」
```

**「規則」欄的合格判準**：下一個模型不需要理解上下文就能照做。
- 不合格：「要更小心 gitignore」
- 合格：「新增要提交的 `.claude/` 子項前，先跑 `git check-ignore -v <路徑>` 確認沒被忽略」

## MAINT-3 修改流程（動任何 playbook 規則時）

1. 備份：`cp <原檔> .claude/backups/<檔名>.<YYYYMMDD>.bak`
2. 修改
3. 自查衝突：Grep 相關關鍵詞掃 `CLAUDE.md` 與其他 playbook，確認新規則沒跟既有條款打架
4. 派 `checker` read-back，驗收條件三條：新舊規則無矛盾／檔內路徑與工具名實際存在／無「弱模型會誤讀」的模糊句
5. commit 訊息寫明：改了哪條、為什麼

**一條規則只有一個家**：同一規則不得在兩個檔各寫一份；第二處一律用編號引用（如「見 DISP-5」）。發現重複就合併並留引用。模板檔（templates.md）內嵌的合約文字是「實例化」不算重複，但改了 DISP-4 回報合約就要同步檢查 templates.md。

## MAINT-4 精簡門檻（防肥大）

| 檔案 | 上限 | 超過就 |
|---|---|---|
| `CLAUDE.md` | 60 行 | 內容下放 playbooks，只留路由與鐵律 |
| 各 playbook | 220 行 | 開精簡任務：合併重複、刪已失效、同一判準的例子最多留一正一反 |
| `lessons.md` | 30 條 | 重複主題升格為 playbook 正式規則；原條目壓成一行移到檔末「歸檔」區 |
| `WORKLOG.md` | 10 節 | 已完成的節各壓成一行結論 |
| `backups/` | 每檔留最近 5 份 | 刪更舊的（git 歷史還在，不會真丟） |

精簡本身也是修改，走 MAINT-3。

## MAINT-5 定期健檢（每累積約 10 個工作 session，或使用者要求時）

- [ ] `lessons.md` 距上次健檢有新條目嗎？**長期零條不是沒踩坑，是制度已被無視**（最常見退化；原理見 letter-to-future-sessions.md）
- [ ] 抽最近一次「宣告完成」：訊息裡有證據嗎（JUDG-2）？
- [ ] `CLAUDE.md` 仍 ≤60 行？
- [ ] 從各 playbook 抽 5 個路徑／工具名，驗證仍然存在（`ls`、ToolSearch）
- [ ] 發現退化：修復＋記一條 lesson（退化本身就是教訓）
