# 對比度稽核

## 為什麼不能用 grep

`docs/design-system.md` 記載了每個 token 的對比值，但**實際頁面上的背景是合成出來的**——
半透明卡片疊在圖片上、巢狀背景、hover 態改了底色。grep 原始碼看不出這些。
`docs/contrast-audit.js` 會走訪每個文字節點、往上找到真正的合成背景色再算對比。

這件事以前要人工開 DevTools 貼一段程式碼。不用再那樣做了。

## 怎麼跑

1. **開 dev server**：`preview_start` 帶 `{ name: "dev" }`。**不要用 Bash 跑 dev server。**
   設定在 `.claude/launch.json`——**該檔被 gitignore，是本機專屬的**（裡面有繞過 Avast
   憑證攔截的 `--use-system-ca`）。新環境沒有它就照 `preview_start` 的說明自己建一份。
2. **導到要檢查的頁面**：`navigate`，路徑用實際要看的那頁。
3. **注入稽核器並取回結果**：讀 `docs/contrast-audit.js` 的內容，用 `javascript_tool` 執行它。
   它回傳 `{ 不合格, 明細 }`。
4. **深色模式也要跑一次**：`resize_window` 帶 `colorScheme: "dark"`，重新注入。
   兩個主題都要過——只驗一個是這類檢查最常見的漏法。
5. **手機寬度也要跑**：`resize_window` 帶 `preset: "mobile"`。
   手機是主要使用場景，而版面在窄寬度會換行、換底色。

## 判準（來自 `docs/design-system.md` 第 2.3 節——動手前請直接讀那節）

- 內文 **≥ 4.5:1**；大字（≥18.66px 粗體或 ≥24px）與 UI 元件 **≥ 3:1**。
- **交易頁面（結帳、付款、退款）一律用內文標準**，不適用大字的寬鬆值。
- `tea-text-light` (`#6B8872`) **不合 AA，不可用於內文**——量到它就是實作用錯 token。

### ⚠️ 對比度不適用於警示色——這條最容易搞錯

低庫存、表單錯誤、超商須知、超重提示這類**要被看見**的東西，
**不要拿 4.5 這個數字去「修」它們**。

WCAG 對比度量的是可讀性，不是顯著性。警示靠彩度與色相差異抓住視線，不是明度差。
2026-08-08 曾把警示色全面換成低彩度版本，對比數字全面上升（低庫存 2.15 → 7.09、
表單錯誤 3.67 → 7.60），業主評語是「顏色變深反而無法起到提醒作用，下意識會忽略」，
**全數回退**。把彩度砍掉三分之二去換對比數字，等於把警示變成裝飾。

**所以回報時要分類**：不合格節點屬於「內文／標籤」還是「警示」。後者不是待辦。

### 已知的合規例外

`docs/design-system.md` 2.3 節末有一張「業主拍板的已知取捨」表，**列在裡面的不算待辦**。
回報前先比對那張表，不要把已經決定接受的東西又報一次。

## 回報

列出不合格節點：選擇器、量到的比值、前景／背景色、所在頁面與主題。
**不要順手改顏色**——顏色是設計系統的約束，改動要照 `docs/design-system.md`
的「如何修改本文」一節走，並先問使用者。
