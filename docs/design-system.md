## 一、三條設計原則

### 1. 產地即證據，介面是茶席

信任來自真實：紀實照片、海拔、產地、40 年敘事永遠是視覺主角。米白為席、深綠為器。
**禁止裝飾性特效搶戲**——repo 裡閒置的 `border-beam` 這類效果不進前台。

### 2. 交易時刻，清晰壓倒氣氛

凡涉及錢與名額（結帳、預約付款、折抵、退款梯度、剩餘名額），**資訊層級、AA 對比、
tabular 數字、五態完整性**（載入／空／錯誤／成功／禁用）優先於品牌氛圍。

> 氛圍留給瀏覽，確定感留給付款。

### 3. 一份茶單，前後台同源，且 token 平台無關

前台商店、管理後台、Email、OG 圖共用同一套 token。任何新 token 必須同時在
「前台敘事密度」與「後台數據密度」下成立。

**平台無關是硬性條件**：設計決策存在 CSS 變數層，元件只引用語意名。

```
❌ className="rounded-2xl shadow-sm p-6"      // 字面值，一行都帶不到 React Native
✅ className="rounded-card shadow-resting p-card"  // 語意名，可導出成 RN theme
```

理由：`--radius-card: 1rem` 可用腳本轉成 React Native 的 theme 物件；`rounded-2xl` 不行。
現在做是改名字，等 App 開案再做是重寫全站。

### 2.1.1 淺底是三層，而且順序有意義

| 層 | 值 | 明度 | 用在哪 |
|---|---|---|---|
| `tea-cream` | `#F5F0E8` | 最暗 | 首頁第一段、製茶工藝段、Header |
| `tea-cream-light` | `#FAF7F2` | 中 | 交易與會員動線的整頁底（購物車、結帳、登入、訂單結果、會員中心⋯） |
| `white` | `#FFFFFF` | 最亮 | 卡片、以及漸進序列的最後一階 |

**這三層是拿來排序的，不是拿來單獨挑一個用的。** 首頁走
`cream → cream-light → white → tea-text（深）`，關於我們走 `white / cream-light` 交替。

> ⚠️ **不要因為「兩兩只差 2%」就把中間層收掉。** 2026-08-08 我這樣做過一次，
> 業主看 preview 立刻發現首頁「本季精選」與「茶山體驗」變同色、關於我們有三段連成一片，
> 全數回退。
>
> 錯在**量錯了東西**：兩兩比對確實只差 2%，但這三段是*依序變亮*的，
> 累積 4.3% 且有方向。方向感不會出現在「兩個色的對比值」裡——
> 那是一個關於**序列**的設計，卻拿比較兩個色的尺去量。
> 業主的原話是「好看的漸層」，那正是這個累積效果。

分派原則：

| 區塊型態 | 底色 |
|---|---|
| 有漸進序列的行銷頁（首頁、關於我們） | 依序列排，見上 |
| 交易／會員的整頁底 | `bg-tea-cream-light` |
| 卡片 | `bg-white` |
| 情緒高點 | `bg-tea-text` |

白卡壓在 `cream-light` 上只差 2%，看起來很弱——**但那是刻意的**，卡片靠邊框與陰影分層，
底色負責的是整頁的漸進而不是單張卡的對比。

`Header` 是 `bg-tea-cream`，與首頁第一段同色，靠 `border-b` 與 `shadow-resting` 分層。

改動淺底後的驗證方法：在 DevTools Console 掃出「不透明背景 == 最近的不透明祖先背景」
且看起來像卡片（有圓角或 padding）的元素——但**先確認你要解的是真問題**：
微弱的層次不等於沒有層次，序列裡的每一階都可能是刻意的。

### 2.1.2 兩個邊框色的分工

`tea-green-pale` 與 `tea-cream-dark` 曾經**都寫著「邊框、分隔」**，沒有分工。
那是實作時隨手用綠的根源——兩個都合法，就等於沒有規則。

| 用途 | 用哪個 | 為什麼 |
|---|---|---|
| 卡片外框（白卡壓在 cream 底上） | `tea-green-pale` | 對白卡 1.43、對米底 1.26 |
| 白卡**內部**的分隔線、表格橫線 | `tea-cream-dark` | 只需與白色有差（1.22），不必對抗米底 |

**不要把卡片外框改成 `tea-cream-dark`**：它對米底的對比只有 **1.08**，
比「白卡 vs 米底」本身的 1.13 還低——邊框會直接消失。2026-08-08 實測，
當時正是想「把綠邊框中性化」才發現這條路走不通。

順帶一提：`tea-green-pale` 作為邊框其實非常淡（1.26–1.43），
**它「綠」的感覺遠低於出現次數（140 處）給人的印象**。統計密度不等於視覺權重。

### 2.1.3 製茶工序色票（`process-*`）

`/process` 專用的敘事色票，用來表達每道工序的**溫度**。沿用 `status-*` 的成對慣例：
無後綴是文字色、`-soft` 是底色。

| Token | 值 | 工序 |
|---|---|---|
| `process-sun` / `-soft` | `#D97706` / `#FFFBEB` | 日光萎凋 |
| `process-indoor` / `-soft` | `#15803D` / `#F0FDF4` | 室內萎凋、再乾 |
| `process-fire` / `-soft` | `#EA580C` / `#FFF7ED` | 炒菁 |
| `process-ferment` / `-soft` | `#B91C1C` / `#FEF2F2` | 發酵 |
| `process-roast` / `-soft` | `#B45309` / `#FFFBEB` | 初乾、焙火（底色與日光同值） |

**不帶溫度的工序用品牌色**：採摘、浪菁、包裝用 `tea-green-mist` + `tea-green`，
揉捻、團揉用 `tea-cream` + `tea-text`。

**為什麼獨立成一群，而不是收進 `tea-*` 或 `status-*`**：它們不是品牌色也不是狀態色，
是這一頁的敘事工具。彩度 0.137–0.194，明顯高於品牌 `tea-green` 的 0.0476——
**這個彩度差才是它們「看起來不像同一套系統」的原因，不是「不在色盤裡」**。
2026-08-08 小江拍板保留原值；值原封不動沿用先前的 Tailwind 預設色，收編時逐一
從建置產物比對確認 10 個 token 渲染值恆等。

**已知取捨**：12 組配對裡 6 組未達 AA 4.5——`witherSun` 3.07、`fix` 3.35，
以及 `pick`／`shake`／`pack` 2.70、`dryFinal` 2.91。**後四組不合格的原因是品牌綠
（`text-tea-green`）而不是工序色**，與 2.3 節那幾項同源。**不要為了補這幾組而降彩度**
——理由見 2.3 的「對比度不適用於警示色」。

`/process` 另有一組色盤外用色未收編：茶種漸層（`ProcessContent.tsx:22-26` 的
`from-green-100 to-emerald-200` 等 5 組）。它是茶種標記不是工序色票，暫列已知例外。

### 2.1.4 觸控目標

手機是主要使用場景，可點擊元素的**點擊區**（不是字級）至少 24px 高——
WCAG 2.2 的 AA 門檻。Apple 建議 44pt、Material 建議 48dp，能給就給。

**手法：用 padding 撐點擊區，不要用 margin 或行高。** 2026-08-08 修 Footer 時，
連結是 `display: inline` + `space-y-3`，點擊區只有 18px（連 AA 都沒過，
手機上很容易點錯行）。修法是 `block py-2` 並把 `space-y-3` 縮成 `space-y-1`——
**padding 換掉 margin**，點擊區 18→36px 而視覺行距只從 36 變 40px。
`block` 讓寬度撐滿整欄，整行都可點，手機上更好按。

驗證方法：在 375px 視窗掃 `a, button`，找出 `getBoundingClientRect().height < 24`
且有文字的元素，結果應為 0。

### 2.2 語意層（`globals.css` 的 `:root`）

元件應優先用語意名，而非直接寫 `tea-*`。

|---|---|---|
| `--background` | `#FFFFFF` | 第六波回退到 Production 的純白；各區塊自帶 `bg-` |
| `--foreground` | text `#3D4A42` | 8.71:1 |
| `--card` / `--popover` | `#FFFFFF` | 卡片浮在米白上才有層次 |
| `--primary` | green-ink `#58745F` | 白字 5.15 |
| `--primary-foreground` | cream-light | 4.82:1 |
| `--secondary` / `--accent` | green-mist `#EBF3EE` | — |
| `--secondary-foreground` | green-ink | 4.56:1 |
| `--muted` | cream `#F5F0E8` | — |
| `--muted-foreground` | text-muted `#637169` | 4.52:1 |
| `--destructive` | `#BB483F` | 白字 5.11、當文字 ≥4.50 |
| `--border` / `--input` | cream-dark `#EDE8DC` | — |
| `--ring` | green-ink `#58745F` | 淺底皆 ≥4.54 |
| `--chart-1..4` | 茶綠明度序列 | — |
| `--chart-5` | 土黃 | 類別型圖表的區辨色，避免全綠無法分辨 |

### 2.3 對比度基準（強制）

- **內文 ≥ 4.5:1**（WCAG AA）
- **大字（≥18.66px 粗體 或 ≥24px）與 UI 元件 ≥ 3:1**
- 交易頁面（結帳、付款、退款）一律以內文標準檢查，不適用大字寬鬆值（原則 2）

> ⚠️ **對比度不適用於警示色。**
>
> WCAG 對比度量的是**可讀性**（看不看得清楚），不是**顯著性**（會不會被注意到）。
> 警示要抓住視線，靠的是**彩度**與周圍的色相差異，不是明度差。
>
> 2026-08-08 我把全站警示色從 Tailwind 的鮮豔色換成低彩度 `status-*`，對比數字全面上升
> （低庫存 2.15 → 7.09、表單錯誤 3.67 → 7.60），業主的評語是
> 「都變醜且也沒有比較好使用，顏色變深反而無法起到提醒作用，下意識會忽略」，全數回退。
>
> 亮橘 `#F59E0B` 對比只有 2.15 卻會跳出來；深棕 `#92400E` 對比 7.09，看起來卻像
> 普通深色文字。**把彩度砍掉三分之二去換對比數字，等於把警示變成裝飾。**
>
> 所以：低庫存、表單錯誤、超商須知、超重提示這類**要被看見**的東西，
> 沿用線上版的鮮豔色，不要拿 4.5 這個數字去「修」它們。內文與標籤才適用上面的判準。

**已知不合格——業主拍板的已知取捨，不列入待辦**（實算結果，非估計）：

> ⚠️ **2026-09-02 已重做，本節的舊「已知取捨」不再適用。**
> 下方保留歷史脈絡，是為了讓再下一次改動知道這件事被翻過兩次、各自的理由是什麼。

**現行對應表**（2026-09-02 起）：

| 用途 | 用哪個 | 對比 |
|---|---|---|
| 主要按鈕（綠底白字） | `bg-tea-green-dark` | 白字 **4.74** |
| 按鈕 hover／按壓 | `bg-tea-green-ink` | 白字 **5.15** |
| 連結、選中態、eyebrow（淺底上） | `text-tea-green-ink` | 白 5.15／米白 4.54 |
| 次要內文與標籤 | `text-tea-text-muted` | 白 5.13／米白 4.52 |
| **價格與應付金額** | `text-tea-text` | 白 **9.31** |
| 折扣、點數、免運等正面訊號 | `text-tea-green-ink` | 維持綠色——那是訊號不是價格 |
| **深色區塊（`bg-tea-text`）上的小標與圖示** | `text-tea-green-pale` | **6.52** |

`text-tea-light`／`text-tea-green` 降級為**純裝飾**：大面積底色、分隔線、
純色塊（進度條、打字動畫圓點）、以及深色底上已達 3.0 的 SVG 圖示（Footer 的
3 處 `text-tea-green` 在 `#3D4A42` 上是 3.05，**刻意保留**——往深改會讓它消失）。

#### 這件事被翻過兩次

**第一次（2026-08-04 → 08-06）**：39 檔全面遷移後回退。理由是遷移後整體明度過沉，
與品牌想要的清透茶席感不符。同期一併回退的還有警示色、淺底收斂、五個頁面的段落底色。

**第二次（2026-09-02）**：業主重新評估後決定重做。這次避開上次結果的三個做法：

1. **分批**——交易動線／共用元件／行銷頁三個獨立 commit，可以單獨回退其中一批，
   而不是像上次那樣 37 檔一起改、一起退。
2. **按鈕用 `green-dark`(4.74) 而非 `green-ink`(5.15)**，就是上一版本節末尾寫的放亮配方。
3. **深色底往淺色走**。上次沒有這條，這次實測抓到 8 處：深墨區塊上的小標原本
   `text-tea-green` 在 `#3D4A42` 上是 3.05（剛好過 UI 門檻），一律改深後掉到 **1.81**。

> **教訓：批次替換顏色時，「一律改深」在有深色區塊的頁面必然出錯，而 grep 看不出來。**
> 只有實測合成後的背景才抓得到——用 `docs/contrast-audit.js`，不要用 grep 驗收。

**價格改用墨色，逆轉了 2026-08-08「價格維持 tea-green」的拍板。**依據是實測 17 個
高質感品牌網站（一保堂／虎屋／中川政七／無印／KINTO／Aesop／Aman／Loro Piana／
Bottega／Belmond／六善／星のや／涵碧樓／茶籽堂／八代目儀兵衛／たねや／掌生穀粒），
它們的**內文彩度中位數是 0.000**，價格一律用中性墨色不套品牌色。
其中茶籽堂的底色 `#F8F4EC`（L .968 C .011 H85）與本站 `#F5F0E8`（L .957 C .012 H80）
幾乎同色，可作為「同色系也能做出不同質感」的對照組。

**仍不動的**：警示色（見上方警告框）、`process-*` 工序色票、淺底三層序列（見 2.1.1）。

### 2.4 深色模式

`.dark` 的值已備齊且全數通過 AA，但**目前不會生效**——`tailwind.config.ts` 沒有 `darkMode`
設定、專案也沒有 ThemeProvider。這是刻意的：0 個業務元件支援 `dark:`，真開等於全站再走一遍，
而真實需求只有「後台清晨看單」。

**預設模式是淺色**，品牌識別建立在 cream 底上。深色實作綁在後台重構那一波。

## 三、字體

| 變數 | 字型 | 來源 |
|---|---|---|
| `--font-latin` | Geist | `next/font`（拉丁字） |
| `--font-sans` | Noto Sans TC | `next/font`（中文內文） |
| `--font-serif` | Noto Serif TC | `next/font`（標題） |

- `font-sans` 的實際鏈：`Geist → Noto Sans TC → sans-serif`。拉丁字走 Geist、中文回退 Noto。
- `h1`–`h3` 由 `globals.css` 強制襯線，不需逐處加 `font-serif`。
- **已載入字重**：Sans `400/500/600/700`、Serif `400/600/700`。用其他字重會觸發瀏覽器假造。
- **禁止**在 CSS 用 `@import` 拉字型（render-blocking）。要加字型一律走 `next/font`。

### 3.1 字級尺度（內文端）

| Token | 值 | 行高 | 用途 |
|---|---|---|---|
| `text-caption` | 12px | 1.6 | 徽章、法律條款、表格註記 |
| `text-label` | 14px | 1.55 | 介面標籤、按鈕、表單、表格內容 |
| `text-body` | 16px | 1.8 | 一般內文 |
| `text-body-lg` | 18px | 1.85 | 敘事段落、導言 |

**為什麼要建這一階**：診斷時前台 `text-xs` 210 處 ＋ `text-sm` 345 處＝**555**，
而 `text-base` 只有 **14** 處——整站幾乎沒有正常閱讀大小的文字，
四十年的故事用後台的字級在講。這是啞鈴分布，不是尺度。

**行高刻意比 Tailwind 預設寬**。預設 `text-base` 是 1.5，對中文敘事太緊；
CJK 舒適區在 1.7–1.9。**放寬行高的效果不亞於放大字級**，兩者要一起做。

**套用判準（三分法，不是全部放大）**：

| 類型 | 處理 | 例 |
|---|---|---|
| 敘事型內文 | 升到 `text-body` / `text-body-lg` | 品牌故事、商品描述、體驗簡介、預約須知 |
| 介面標籤 | 維持 `text-label`(14px) | 按鈕、表單 label、「查看全部」、麵包屑 |
| 真 metadata | 維持 `text-caption`(12px) | 徽章、eyebrow 小標籤、編號、時長人數 |

> `tracking-[0.3em] uppercase` 的 eyebrow 小標籤**刻意保持 12px**——
> 它的作用是節奏標記不是閱讀內容，放大反而破壞層次。

**標題端的字級**沿用 Tailwind 既有尺度。既有的 `text-sm` / `text-xs` 也保留可用，
這是漸進遷移不是一次換掉全站；新寫的介面請直接用語意 token。

### 3.2 標題字重（2026-09-02 起）

| 層級 | 字重 | 為什麼 |
|---|---|---|
| `h1` / `h2` | `font-normal`（400） | 展示與段落標題 |
| `h3` | `font-semibold`（600） | 卡片標題。降到 400 會與同為 400 的內文失去重量差、只剩字級差，卡片會糊掉 |

**依據**：實測 17 個高質感品牌網站，**整頁最大字級一律是 400 字重，沒有一個例外**
（Aman 31px/400、虎屋 28px/400、Loro Piana 26px/400、Belmond 64px/400、
一保堂 21px/500）。700 的明體中文大字是賣場招牌的語彙。

**只用已載入的 400／600／700**。`font-medium`(500) 在 Serif 沒有載入，會觸發瀏覽器假造——
要用 500 得先在 `layout.tsx` 的 `notoSerifTC.weight` 補上，那是一次額外的字型下載。

### 3.3 字距（2026-09-02 起）

| Token | 值 | 用途 |
|---|---|---|
| `tracking-display` | `0.04em` | h1／h2 展示型標題（前台 93 處全數套用） |
| `tracking-eyebrow` | `0.25em` | eyebrow 小標籤（收斂落點，尚未套用；現況散寫 `[0.25em]`／`[0.3em]`） |

> **CJK 大標的字距是正的，不是負的。** 負字距是拉丁文大字的做法；中文字身本來就是方框，
> 收緊只會讓字擠在一起。實測日系品牌：一保堂 h2 `+3.57px`（約 +0.17em）、Aman `+0.5px`。
> `0.04em` 是「看得出鬆開了、但還不到標語感」的落點；再大就進入 eyebrow 的語彙。

**h3 不加字距**：20px 的卡片標題加字距會讓「標題像標語」，而它的角色是被掃視不是被朗讀。

### 3.4 標題字級的上限

Hero 從 `md:text-9xl`(128px) 降到 `sm:text-6xl`(60px)。依據是實測 17 個品牌的
**整頁最大字級**：上限是 Belmond 的 64px，中位數約 28px（Aman 31／虎屋 28／
Loro Piana 26／一保堂 21／中川政七 16）。**128px 是樣本上限的兩倍。**

> 靠字級撐場面是賣場的做法。這些品牌的視覺衝擊來自**攝影**不是字——
> 它們的照片覆蓋率是 50–85%（六善 84.5／茶籽堂 80.9／八代目 68.5／Belmond 49.9），
> 本站是 36.9%。要更有份量該補的是照片，不是字級。

手機維持 `text-5xl`(48px)：小螢幕的品牌名本來就要夠大才立得住。

## 四、非顏色 token

質感八成來自這一層，不是配色。命名由現況統計反推。

### 4.1 圓角

| Token | 值 | 用途 |
|---|---|---|
| `rounded-inline` | `0.5rem` | 內嵌訊息條、後台輸入框 |
| `rounded-control` | `0.75rem` | 表單控制元件、次要按鈕、chip |
| `rounded-card` | `1rem` | 卡片、面板 |
| `rounded-showcase` | `1.5rem` | 大型展示區塊 |
| `rounded-pill` | `9999px` | 藥丸 CTA、徽章、頭像 |

### 4.2 陰影

**一律用茶墨色 `rgb(61 74 66)`，不用 Tailwind 預設的純黑。** 純黑陰影壓在米白上會透出灰調，
暖色陰影才不會讓米白顯髒——這是「看起來貴」與「看起來預設」的實際差別。

| Token | 用途 |
|---|---|
| `shadow-resting` | 卡片靜置 |
| `shadow-raised` | 卡片 hover |
| `shadow-float` | 下拉、浮層 |
| `shadow-modal` | 對話框、燈箱 |

> ⚠️ boxShadow 的 key **不可命名為 `card`**：`card` 已是顏色 key，同名會讓 Tailwind 同時產出
> 「陰影」與「陰影顏色」兩條 `.shadow-card`，後者在後會覆寫前者。

### 4.3 動態

| Token | 值 | 用途 |
|---|---|---|
| `duration-fast` | 150ms | 顏色、透明度等微互動 |
| `duration-base` | 200ms | 標準互動（全站主力） |
| `duration-slow` | 300ms | 位移、展開收合 |
| `duration-reveal` | 500ms | 大面積變化，如圖片 `group-hover:scale` |
| `ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | 一般 |
| `ease-exit` | `cubic-bezier(0.4, 0, 1, 1)` | 離場 |

`prefers-reduced-motion: reduce` 已全站支援（動態走 CSS 變數，改寫變數即收斂）。

### 4.4 間距節奏

| Token | 值 | 用途 |
|---|---|---|
| `*-gutter` | `1rem` | 版面左右安全邊 |
| `*-card` | `1.5rem` | 卡片內距 |
| `*-card-lg` | `2rem` | 大卡片內距 |
| `*-section` | `4rem` | 區塊垂直節奏（行動）——**手機一律用這個**，不套 -lg/-xl |
| `*-section-lg` | `6rem` | 區塊垂直節奏（桌機）＝「快段」 |
| `*-section-xl` | `10rem` | 「慢段」，敘事型段落。**只寫成 `py-section md:py-section-xl`** |

**快慢比是 1.67**（160 : 96）。2026-09-02 從 8rem(128px) 提高到 10rem——
原本 128:96＝1.33，在感知上太接近均勻，而均勻等於沒有節奏。

> **要拉開節奏對比就加大慢段，不要壓縮快段。** 我原本建議 160/80 去湊 2:1，
> 但縮小標準節奏會讓整體留白變少，與「更透氣」的目標相反，因此只動慢段。

手機不套 -lg/-xl 是 2026-08-27 業主實測拍板：手機一屏只裝得下一張卡，
多 32px 就是「還要再滑一次」。節奏感在大螢幕才看得出來。

版面慣例：`max-w-7xl mx-auto px-4 sm:px-6 lg:px-8`（左右內距寫法全站 54 處、`max-w-7xl` 29 處；
其餘容器寬度依內容取 `max-w-2xl` ~ `max-w-5xl`）。勿另創新的內距組合。

## 五、外包視覺／生成工具的交付規格

**不要接受程式碼交付。** 每個生成工具都自帶一套隱形設計系統（它習慣的圓角、陰影、灰階）。
貼一頁進來就是把第二套系統偷渡進 codebase；貼三頁，就會變成「每頁單看都好看，整站不像同一個品牌」。

### 交付物

| 階段 | 交付 |
|---|---|
| 定調 | Hero 方案**圖**（3 張），不要 code |
| 說明 | 文字說明所用的字級比例、間距節奏、陰影強度 |
| 落地 | 由本專案把圖翻譯成 token 與元件 |

### 給生成工具的約束（直接貼）

```
品牌：台灣阿里山高山茶，家族四十年，自產自銷。
調性：安靜、可信、有手作痕跡；不是精品百貨的華麗。

色彩：主綠 #7D9B84、互動綠 #58745F、米白 #F5F0E8 / #FAF7F2、文字 #3D4A42。
      只出這三個色相的階調，不要引入新色相。
字體：中文標題 Noto Serif TC、內文 Noto Sans TC；拉丁字 Geist。
      可用字重僅 400/500/600/700。
圓角：8 / 12 / 16 / 24px 與全圓四階，不要出現其他值。
陰影：一律用 rgb(61 74 66) 的低透明度，不要用純黑。
對比：任何文字對背景 ≥ 4.5:1。
攝影：紀實茶園實拍（信任）與去背棚拍商品（銷售）雙軌，不要 3D、不要插畫。

輸出 Hero + 商品卡 + 一個 section 的圖，並文字說明你用的字級比例、
間距節奏與陰影強度。不要輸出程式碼。
```

## 七、如何修改本文

1. **token 值改動先改程式碼**（`globals.css` / `tailwind.config.ts`），再回頭同步本文。
   本文與程式碼不符時一律以程式碼為準。
2. **新增顏色前先算對比**。不要憑感覺——`#7D9B84` 看起來很像可以配白字，實際只有 3.05。
3. **驗證 Tailwind 產物一律用 `npm run build` 的 `.next` 產物**。
   `npx tailwindcss` CLI 讀不到本專案的 TS config，跑出來的東西沒有參考價值。
4. 三條設計原則的改動**先問使用者**——那是品牌決策，不是技術決策。
