# ai-chat-api Specification

## Purpose
AI 客服的 API 端點：system prompt 組裝、語系感知回應、頻率限制、對話脈絡與錯誤處理。

## Requirements

### Requirement: Chat API endpoint
The system SHALL expose a POST `/api/chat` endpoint that accepts a JSON body with `messages` (array of `{role, content}`) and `locale` (string), and returns a streaming response from Gemini API.

#### Scenario: Successful chat request
- **WHEN** a POST request is sent to `/api/chat` with valid messages and locale
- **THEN** the system returns a streaming text response (content-type: text/event-stream) generated by Gemini 2.0 Flash

#### Scenario: Empty messages array
- **WHEN** a POST request is sent with an empty messages array
- **THEN** the system returns HTTP 400 with an error message

### Requirement: System prompt with knowledge base
The system SHALL construct a system prompt that includes the tea shop's knowledge base (products, experiences, FAQ) and instructs the AI to only answer based on provided information.

#### Scenario: AI responds within knowledge scope
- **WHEN** a user asks about a tea product that exists in the knowledge base
- **THEN** the AI responds with accurate information from the knowledge base

#### Scenario: AI declines out-of-scope questions
- **WHEN** a user asks a question unrelated to tea or the shop
- **THEN** the AI politely declines and suggests the user contact the shop via LINE for further assistance

### Requirement: Locale-aware responses
The system SHALL switch the system prompt language based on the `locale` parameter — Chinese for "zh", English for "en".

#### Scenario: Chinese locale request
- **WHEN** locale is "zh"
- **THEN** the AI responds in Traditional Chinese

#### Scenario: English locale request
- **WHEN** locale is "en"
- **THEN** the AI responds in English

### Requirement: Rate limiting
The system SHALL limit chat requests to 10 per minute per IP address.

#### Scenario: Within rate limit
- **WHEN** a client sends fewer than 10 requests per minute
- **THEN** all requests are processed normally

#### Scenario: Exceeding rate limit
- **WHEN** a client exceeds 10 requests per minute
- **THEN** the system returns HTTP 429 with a user-friendly message

### Requirement: Conversation context
The system SHALL accept up to 10 recent messages as conversation context for multi-turn dialogue.

#### Scenario: Multi-turn conversation
- **WHEN** a request includes previous messages in the conversation
- **THEN** the AI considers the conversation history when generating the response

#### Scenario: Context exceeds limit
- **WHEN** a request includes more than 10 messages
- **THEN** the system uses only the most recent 10 messages

### Requirement: Error handling
The system SHALL handle Gemini API failures gracefully and return a user-friendly error message.

#### Scenario: Gemini API unavailable
- **WHEN** the Gemini API returns an error or times out
- **THEN** the system returns HTTP 503 with a message suggesting the user try again later or contact via LINE

### Requirement: Usage logging
The system SHALL log each chat request with a timestamp and locale for basic usage monitoring via Vercel Function Logs.

#### Scenario: Request logged
- **WHEN** a chat request is processed (success or failure)
- **THEN** the system logs a structured entry with timestamp, locale, and status to console

### Requirement: Global daily usage cap

AI 客服 API SHALL 在每 IP 限流之外，額外套用全站每日總呼叫量上限，以保護外部模型（Groq）額度不被輪換 IP 的攻擊者刷爆。上限 SHALL 可由環境變數 `CHAT_DAILY_LIMIT` 設定，未設定時預設為 1000。

#### Scenario: 全站每日上限達到

- **WHEN** 全站當日（UTC）累計聊天請求數已達 `CHAT_DAILY_LIMIT`
- **THEN** 系統 SHALL 回應 HTTP 429 並提示改用 LINE 聯繫，不再呼叫外部模型

#### Scenario: 跨日重置

- **WHEN** 進入新的 UTC 日期
- **THEN** 系統 SHALL 以新的每日計數重新累計
