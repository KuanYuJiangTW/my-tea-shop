# 提案：品飲組（入門組合 SKU）

## Why

**首購門檻太高，而且中間帶是空的。** 2026-08-12 盤點真實已付款訂單（排除測試單後 6 筆、3 個客人），商品小計逐筆是 `400, 400, 400, 400, 1020, 1250`——客人要嘛買一包就走，要嘛跳到湊免運，**400 與 1,020 之間沒有任何一筆**。

新客的實際處境是「花 400 元買一包沒喝過的茶」，這是高風險決策。品飲組把它換成「花 600 多元試三種」，風險感反而更低。

**而且毛利更好。** 75g 的定價是 150g 的 60%，但茶葉成本只有 50%：

| 商品 | 150g 毛利率 | 75g 毛利率 |
|---|---|---|
| 阿里山高山烏龍 | 59.4% | **66.1%** |
| 蜜香紅茶 | 50.0% | **58.3%** |
| 阿里山金萱 | 53.6% | **63.1%** |

賣兩包 75g（480 元）比賣一包 150g（400 元）多賺 80 元，**茶葉用量完全相同**。這是少見的「客人門檻更低、你賺更多」。

## What Changes

- 新增「品飲組」商品：三款各 75g（阿里山高山烏龍、蜜香紅茶、阿里山金萱），定價待業主拍板（單買合計 700 元）
- 品飲組的**庫存與扣減連動三款茶的 `stock_75g`**：可售量取三者最小值，下單時三款各扣 1
- 商品列表與首頁呈現品飲組，文案定位為「第一次買茶的人從這裡開始」
- 購物車、結帳、訂單明細、出貨與退款流程能正確處理這個 SKU

**BREAKING**：無。純新增。

**刻意不做**：不做「自由選三款」的客製組合。那會讓庫存扣減與缺貨判斷變成 N 選 3 的組合問題，而目前只有三款茶有 75g 庫存——彈性沒有需求支撐。

## Capabilities

### New Capabilities

- `bundle-products`：組合商品的資料模型、可售量計算（取成分最小值）、加入購物車與建單時的成分扣減、缺貨判斷與顯示。

### Modified Capabilities

- `product-ordering`：現行規格描述的是單一商品的庫存扣減。要求擴充為「建單時若商品為組合，需改扣其成分的庫存」，且扣減仍須維持原有的原子性與失敗回滾行為。

## Impact

**資料庫**
- 新表 `product_bundles` 與 `product_bundle_items`（組合 → 成分商品＋規格＋數量），或在 `products` 加 `bundle` 型別欄位——由 design 決定
- **高風險區**：碰庫存扣減，依 CLAUDE.md 鐵律 4，動之前必讀 `openspec/specs/product-ordering/`，改完必跑 `npm run test`

**程式碼**
- `src/lib/products.ts`（取貨與可售量）、`CartContext`、`ProductCard`／`TeaBagCard`、四條建單 API 的庫存扣減段、後台訂單明細顯示

**現況限制（會影響上架時程）**
- `stock_75g`：烏龍 50、蜜香紅茶 53、金萱 48；**紅烏龍與四季春都是 0**，所以組合成分只能是前三款
- 品飲組單買合計 700 元，**低於國內免運門檻 1,000**——這不是缺點，是加購動線（買一組再加一包 150g 就免運），但文案要講清楚

**未知數**
- 組合的外盒與包材成本業主尚未提供，會影響定價
